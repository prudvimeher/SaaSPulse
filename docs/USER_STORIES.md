
# SaaSPulse — User Stories & Acceptance Criteria

**Product:** SaaSPulse  
**Product Type:** SaaS Business Analytics Dashboard  
**Target Users:** SaaS Founders and CEOs  
**Document Type:** User Stories & Acceptance Criteria  
**Version:** 1.0

---

# 1. Executive Overview

## US-01: View Key Business Metrics

**Priority:** P0

**User Story:**

As a SaaS founder, I want to see my company's key business metrics in one place so that I can quickly understand its overall performance.

**Acceptance Criteria:**

- AC-01: When the user opens the dashboard, MRR, ARR, total customers, and churn rate are displayed.
- AC-02: Each metric displays a clearly formatted value.
- AC-03: MRR equals the sum of active recurring subscription revenue.
- AC-04: ARR equals MRR multiplied by 12.
- AC-05: If metric data is unavailable, an appropriate empty state is displayed.
- AC-06: If the API request fails, an appropriate error state is displayed.

## US-02: Compare Business Performance

**Priority:** P0

**User Story:**

As a SaaS founder, I want to compare current business metrics with the previous period so that I can understand whether my business performance is improving or declining.

**Acceptance Criteria:**

- AC-01: Current and previous period values are displayed for supported metrics.
- AC-02: The percentage change between the two periods is calculated correctly.
- AC-03: Positive and negative changes are visually distinguishable.
- AC-04: If the previous period value is zero, the application handles percentage change without division errors.
- AC-05: Comparisons update when the reporting period changes.

## US-03: View Revenue Performance Trends

**Priority:** P0

**User Story:**

As a SaaS founder, I want to view revenue trends over time so that I can identify business growth or decline.

**Acceptance Criteria:**

- AC-01: Revenue performance is displayed in a chart.
- AC-02: The chart represents revenue across the selected reporting period.
- AC-03: Changing the reporting period updates the chart.
- AC-04: The chart displays meaningful labels and values.
- AC-05: An appropriate empty state is displayed when revenue data is unavailable.

# 7. Business Rules and Definitions

The following definitions must be consistent throughout the application.

| Metric | Definition |
|---|---|
| MRR | Sum of active recurring subscription revenue, normalized to a monthly amount |
| ARR | MRR multiplied by 12 |
| Customer churn rate | Customers lost during a period divided by customers at the beginning of that period |
| Customer retention rate | Customers from the beginning of a period who remain customers at its end, divided by customers at the beginning |
| New customers | Customers acquired during the selected reporting period |
| Active customers | Customers with an active subscription at the relevant reporting date |
| Lost customers | Customers whose subscriptions ended during the selected reporting period |

**Additional rules:**

- All date-based metrics must use consistent reporting-period boundaries.
- Calculations must handle zero denominators safely.
- Currency values must use a consistent currency format.
- Customer counts must not be confused with subscription counts.
- Revenue calculations must use the same reporting scope when comparing totals and breakdowns.
- The same metric must follow the same definition wherever it appears.

# 9. Definition of Done

A user story is considered complete only when:

- All acceptance criteria pass.
- The feature behaves correctly with valid data.
- Empty and error conditions are handled.
- The interface works across supported screen sizes.
- Relevant automated tests pass.
- No known critical defects remain.
- The implementation has been reviewed.
- The feature is integrated into the application without breaking existing functionality.
